# SHADOW

일정 본체 주변의 준비·이동·회복 시간과 비용을 함께 보여주는 캘린더입니다. 로그인 없이 로컬에서 사용하거나, 선택적으로 계정·서버 저장·공유·외부 캘린더 연동을 사용할 수 있습니다.

## Run locally

```bash
npm install
npm run dev:full
```

Node.js 24가 필요합니다. `http://localhost:5173`을 엽니다. React/Vite 화면과 Node/SQLite 서버가 함께 실행되고, 기본 DB는 `data/shadow.sqlite`입니다. 로컬 캘린더만 필요하면 `npm run dev`로 화면만 실행할 수 있습니다. Windows PowerShell에서 실행 정책 오류가 발생하면 `npm.cmd`를 사용하세요.

외부 연동은 `.env.example`을 참고해 로컬 `.env`를 직접 설정한 후 실행하세요. 실제 키·토큰·DB는 Git에서 제외합니다. 자세한 설정: [서버 운영](docs/server.md), [Google·Outlook·Apple 연결](docs/integrations.md).

## Features

- 일정·유형 CRUD, 그림자와 실제 시간·비용, 15분 스냅 드래그, 충돌 경고
- 일간·주간·월간 보기, 제목/장소 검색, 유형 필터, 표시 기간 시간·비용 통계
- 종일·다일 일정, 일/주/월 반복, 이번 일정만 또는 전체 반복 수정·삭제
- 실행 취소/다시 실행 50단계, JSON 백업/복원, ICS 가져오기/내보내기
- 사용자가 켠 경우에만 준비 시작/일정 시작 브라우저 알림
- 이메일·비밀번호 계정, 사용자별 SQLite 저장, 버전 충돌을 검사하는 기기 간 수동 동기화
- 제목을 지정하는 읽기 전용 공유 스냅샷과 공유 링크 폐기
- Google Calendar·Outlook·Apple iCloud의 전용 SHADOW 캘린더와 생성/수정/삭제 양방향 동기화, 동시 수정 충돌 선택

## Sync workflow

1. `계정·연동`에서 가입/로그인합니다. 로그인 자체는 브라우저 일정을 업로드하지 않습니다.
2. `이 브라우저 데이터를 서버에 저장`을 누릅니다. 다른 기기의 변경으로 서버 버전이 달라졌다면 덮어쓰지 않고 중단합니다.
3. 외부 제공자를 연결한 뒤 `양방향 동기화`를 누릅니다. 전용 SHADOW 캘린더만 변경하며 기존 다른 캘린더에는 쓰지 않습니다.
4. 양쪽에서 변경된 일정은 `SHADOW 서버 버전 사용` 또는 `외부 버전 사용`으로 해결합니다.
5. `서버 데이터 가져오기`로 동기화 결과를 현재 브라우저에 반영합니다. 다른 기기에서도 같은 계정으로 가져올 수 있습니다.

공유는 생성 시점의 복사본이며 이후 변경을 자동 반영하지 않습니다. 링크를 가진 사람은 제목·장소·시간·비용을 볼 수 있으므로 반드시 내용을 확인하세요. 연결 해제는 자격 증명만 제거하며 외부 캘린더를 삭제하지 않습니다.

## Verification

```bash
npm run lint
npm run typecheck
npm run test -- --run
npm run test:server
npm run build
npm run smoke
npx playwright install chromium
npm run test:e2e
```

`npm run verify`는 lint, TypeScript, 단위/컴포넌트 테스트, 실제 HTTP/SQLite 및 제공자 프로토콜 테스트, 빌드를 실행합니다. E2E는 별도 포트의 메모리 DB와 Chromium을 사용합니다. 테스트끼리 같은 포트를 점유하므로 E2E 명령을 동시에 실행하지 마세요.

## 동작 기준

- 시간표는 00:00~24:00 전체를 표시합니다. 준비·귀가·회복 그림자가 자정을 넘으면 전날/다음 날에도 이어집니다.
- 일정을 클릭하거나 Enter 키로 편집할 수 있습니다. 드래그는 잡은 위치를 유지하며 15분 단위로 이동하고, Escape 또는 포인터 취소로 이동을 취소합니다.
- 종일/다일 일정의 드래그는 시간과 길이를 보존해 날짜를 이동합니다. 시간은 편집 패널에서 바꿀 수 있습니다. 반복 일정 드래그는 이번 회차만 변경합니다.
- 월 반복은 같은 날짜를 사용하고 존재하지 않는 날짜는 건너뜁니다. 반복 종료일은 필수이며 최대 5년입니다. 전체 반복 변경 범위는 이미 분리된 회차에 새 시간/비용을 덮어쓰지 않습니다. 전체 반복 삭제는 연결된 회차도 삭제합니다.
- 겹치는 일정은 나란히 표시합니다. 충돌 합계는 현재 보이는 날짜에서 일정 쌍마다 한 번 계산합니다. 3개 이상 겹치면 서로 다른 쌍의 시간이 합산됩니다.
- 모든 시간·비용은 0 이상의 정수이며 그림자는 각 720분, 비용은 항목별 10,000,000원까지 입력할 수 있습니다. 종료 시각의 ‘자정에 종료’는 24:00입니다.
- 유형 기본값을 바꿔도 기존 일정의 시간·비용은 유지됩니다. 사용 중인 유형과 마지막 남은 유형은 삭제할 수 없습니다.
- 모바일에서도 유형 설정이 가능합니다. 편집 패널은 키보드 포커스를 안에 유지하고 Escape로 닫은 뒤 원래 버튼으로 돌아갑니다.
- 손상되거나 지원하지 않는 저장 데이터는 자동으로 덮어쓰지 않습니다. 확인 후 초기화해야 편집을 재개할 수 있습니다. 저장 공간 부족 시 오류를 표시하며 ‘저장 재시도’로 메모리의 변경사항을 다시 저장합니다.

## Privacy and operating limits

- 기본 저장은 브라우저 `localStorage`입니다. 서버 업로드·외부 동기화·공유를 선택할 때만 해당 데이터가 전송됩니다. 분석 도구와 유료 필수 서비스는 없습니다.
- 서버 계정 비밀번호는 scrypt로 해시하고 세션은 HttpOnly 쿠키를 사용합니다. 외부 인증 정보는 별도 환경변수 키로 암호화합니다. 일정 DB/백업 자체는 민감정보이므로 서버 접근 권한과 백업 보관은 운영자가 관리해야 합니다.
- 로그아웃은 브라우저 일정이나 다운로드한 파일을 삭제하지 않습니다. 공유 기기에서는 백업 후 로컬 전체 초기화를 확인하세요.
- 알림은 탭이 열린 동안만 동작합니다. 브라우저가 종료되거나 절전 중이면 보장하지 않습니다. 권한은 사용자가 버튼을 누를 때만 요청합니다.
- ICS는 5MB/5,000개 제한이며 미지원 규칙은 경고하고 원본을 보존합니다. 무기한 반복·복잡한 BYxxx 규칙, 제공자별 편집 예외의 일부 형식은 일반 반복으로 임의 변환하지 않습니다. 상세 제한은 연동 문서를 확인하세요.
- 원격 동기화는 자동 백그라운드/푸시가 아닌 명시적 수동 동기화입니다. 단일 Node 서버 프로세스와 영속 SQLite 볼륨을 사용하세요. 이메일 검증·비밀번호 복구·관리자/결제/지도·네이티브 앱은 포함하지 않습니다.

## Build and deployment

```bash
npm run build
npm start
```

`npm start`는 `dist/`와 API를 같은 서버에서 제공합니다. 로컬에서 이 방식으로 접속할 때는 `SHADOW_ORIGIN`/`SHADOW_PUBLIC_URL`을 실제 주소(예: `http://localhost:8787`)와 일치시키세요. 배포 시 HTTPS, 정확한 origin/OAuth 콜백, 영속 DB, 암호화 키를 설정해야 합니다. 로컬 전용 프런트엔드는 정적 배포가 가능하지만 계정/공유/외부 연동에는 Node 서버가 필요합니다. 자동 배포는 설정하지 않습니다.

Windows의 제한된 실행 환경에서 기존 `dist`를 정리하는 단계가 종료될 경우, `npm.cmd run build -- --emptyOutDir false`로 기존 파일 삭제 없이 빌드할 수 있습니다. 이 방법은 이전 해시 파일을 남기므로 배포용 결과물은 새 출력 폴더에서 생성하세요.

외부 API 테스트는 주입한 프로토콜 응답으로 검증합니다. 실제 Google/Microsoft OAuth 등록·동의 및 Apple 앱 전용 암호 연결은 사용자 소유의 테스트 계정으로 별도 검증해야 합니다. 연결 → 생성 → 양방향 수정/삭제 → 동시 수정 충돌 → 만료 토큰 → 연결 해제 순서로 점검하세요. 자동 테스트 통과가 실계정 연결 성공을 의미하지 않습니다.
